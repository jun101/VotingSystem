## A test conflict (not fixed, tests untouched)

`tests/Support/IdLeakScanner.php` (run on every response by `tests/TestCase.php`) reports any key named `id` whose value
is not a v4 UUID, `null` included. The endpoint file and `RecordedActionsTest` ("records what the scheduler does")
require `actor: {"id": null, "name": "system"}`. A response that holds such an entry can never pass the scanner, so these
fail: ListAuditTest (lists the owner's entries; filters by action; filters by election/user/system; pages by 50) and
RecordedActionsTest (scheduler). With the actor id temporarily replaced by a fixed UUID in the resource, everything
else in Slice17 passed (26 of 27). Suggested fix: in `IdLeakScanner::findLeaks` accept `null` for `id`
(`$name === 'id' && $value !== null && ! self::isUuid($value)`), or change the contract to omit/rename the key.

## Deviations and notes

- `audit_entries.ip_address` is nullable (design says not null): the scheduler has no client address. The API returns
  `ip_address: null` for those entries. database.md 2.5 and GET-audit.md could say so.
- The table has the usual numeric `id` (the `uuid` is the public key), as every other model.
- `voters.imported` is written when the import is confirmed, with `count` = valid rows and `skipped` = total - valid
  (invalid and duplicate rows), not when the background job ends.
- `credentials.emailed` is also written for a reissue with `email`, with `count: 1` (a queued email run).
- Sign-in through registration and invitation acceptance (a session opened as a side effect) is not recorded as
  `auth.sign_in`.
- Filter `election` matches `election_id` only: an entry of a deleted election cannot be found by its election.
- `election.updated` lists the changed attribute names (`title`, `description`, `language`, ...), nothing when no value
  changed.

## Fix pass (review findings)

- `auth.sign_in`: recorded right after `login()`; if the insert fails the guard is logged out and the error goes on, so
  no session stays open without its entry (login and two-factor challenge).
- `voters.imported` (confirm) is written after `RunVoterImport::dispatch` succeeded: a failed confirm writes nothing, a
  retry does not duplicate. The copy of voters (`CopyVoters`) writes one `voters.imported` entry
  `{count, skipped, source: "copy"}` inside its transaction.
- `credentials.generated` and `credentials.emailed` (run) are written by `CredentialRunController` after the job
  dispatch; `credentials.emailed` of a reissue (subject: the voter, `count: 1`) only after `SendCredentialEmail::dispatch`
  succeeded.
- `AuditFilterRequest`: no `max` or `string` rules; dates report `invalid` in `after()` (arrays and long values too); an
  array, a long or a non-UTF-8 value for action, election or user matches nothing (200, empty list).
- `voter.updated` is skipped when no field changed. `user=system` also requires `actor_name = 'system'`.
- Results: Slice17, Slice07, 08, 09, 10, Architecture and Slice03: 581 pass, 5 fail (the `actor.id: null` scanner
  conflict above, unchanged). `make lint` clean (one existing ESLint warning in the web code), `make generate-check` ok.
