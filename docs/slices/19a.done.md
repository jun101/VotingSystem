# Slice 19a (server) - done

Branch `slice/19-security-hardening`. Nothing committed.

## Built

- `php artisan vote-audit:read` (`api/app/Console/Commands/ReadVoteAudit.php`) per
  `docs/api/system/COMMAND-vote-audit-read.md`; connection `audit_reader` in `config/database.php`
  (`DB_AUDIT_READER_*`, falling back to `DB_HOST`/`DB_PORT`/`DB_DATABASE` and the migrator account). It is the one
  place that reads `vote_audit`, with `->table('vote_audit')->where()->get()`; it never writes to the database.
- Absolute session lifetime: `config('session.absolute_lifetime')` (`SESSION_ABSOLUTE_LIFETIME`, 720),
  `App\Http\Middleware\EndExpiredSession` in the `cookie-session` group (and in the priority list, right after
  `StartSession`, so a signed-out request is 401 before the CSRF check). `EndExpiredSession::start()` is called at
  sign-in, after the two-factor challenge, at registration and at invitation acceptance; impersonation does not touch it.
  A signed-in session without a start time (older than this rule) starts counting at its next request.
- `config/platform.php` (`require_two_factor`, `PLATFORM_REQUIRE_TWO_FACTOR`, on only when `APP_ENV` is production);
  `EnsurePlatformAdmin` answers 403 `two_factor_required` after the role check (messages in `lang/fr|en/errors.php`).
  While acting, the session user is the owner and the middleware's `acting` form lets the request through, as before.
- `App\Http\Middleware\AddApiSecurityHeaders`, a global middleware (prepended, so 404, 405, OPTIONS and refused hosts
  carry the headers too). A Cache-Control the route chose (`max-age` or `public`) and file downloads are left alone.
- `docker/proxy/Caddyfile.production` (new) and `Permissions-Policy` in `docker/proxy/Caddyfile`.
- Endpoint files of `docs/api/platform/`: a `403 two_factor_required` row in four files.
